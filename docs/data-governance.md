# Data governance

Status labels follow [technical-documentation.md](technical-documentation.md): **Runs in prototype**, **Simulated**, **Proposed for production**.

## What data the prototype holds

| Data | Origin | Status |
| --- | --- | --- |
| Demo personas, labs, wearable series, assessments | Generated by `prisma/demo.ts` and `prisma/seed.ts` (fictional people) | Synthetic. No real patient data has been used at any stage. |
| Simulated evaluation cohort (400 records, seed 2026) | Generated in memory by `src/lib/evaluation.ts` | Synthetic; never stored |
| Guidance corpus for the assistants | Public documents cited by section and page (`src/lib/rag/corpus.ts`) | Public sources, quoted for reference |

## Controls that run in the prototype

- **Governed entry.** Patients register only with a clinician prescription or partner pairing token, bound to the invited email. Clinician accounts are provisioned, not self-registered (`src/app/api/auth/register/route.ts`).
- **Granular, revocable consent.** Five purposes (care team, labs, wearables, partner, population analytics), each enforced in the API (`src/lib/consent.ts`) and recorded with a timestamp.
- **Purpose limitation.** Stated to users: reproductive data is not used for employment, insurance or other unrelated decisions.
- **Clinician scoping.** Clinicians see and write only cases they prescribed or were assigned (`src/lib/clinician-scope.ts`).
- **Provenance.** Every lab value carries its source (clinician verified, imported, self-reported, recorded earlier) and date. Patients cannot write lab values. Every temperature or sleep reading carries its source (entered by hand, Bluetooth thermometer, Health Connect, Apple Health, Ultrahuman), the device or app name and a source id; only those two reading types are accepted.
- **Release control.** Assessments are clinician-created drafts; patients see only released ones.
- **Authentication.** bcrypt password hashes; HTTP-only, signed JWT session cookies (`src/lib/auth.ts`); role gating in `src/middleware.ts`.
- **Audit log.** Logins, consent changes, assessments, releases, discards, agent proposals and approvals, and FHIR exports are written to `AuditLog` (`src/lib/audit.ts`).
- **Small-group suppression.** Population insight hides groups too small to stay anonymous.

## Gaps, stated plainly

| Gap | Today | Before real patient data |
| --- | --- | --- |
| Encryption at rest | **Applied to sensitive text fields** (names, medical-history flags, clinician notes, assessment inputs and factors, follow-up notes and assistant questions and replies) with AES-256-GCM through a Prisma extension (`src/lib/db.ts`, `src/lib/encryption.ts`, unit tests). Not encrypted: numeric lab values and email addresses. One key in an environment variable; no rotation. Without the key the app writes plaintext. | Managed keys (Azure Key Vault, UAE North) with rotation; fail closed in production if the key is missing; extend to lab values; re-encrypt rows written before the change. |
| Data residency | Prototype database is hosted outside the UAE (AWS us-east-2); the assistants call Azure OpenAI gpt-5-mini in UAE North, with Groq (US) as fallback. Only synthetic data is processed. | Move the database and scoring service to a UAE region (e.g. Azure UAE North, where the LLM already runs); remove the Groq fallback. DoH Responsible AI Standard clause 3.1.4.5.1. |
| Invitation email | When `RESEND_API_KEY` is set, clinician invitations are emailed through Resend (not UAE-hosted). The email is discreet (no health wording, no name) and failures fall back to sharing the link by hand; audit entries record the role, not the address. | Swap `src/lib/email/index.ts` to a UAE-hosted sender (e.g. Azure Communication Services, UAE North) or the clinic's mail system. |
| Multi-factor sign-in | Not built | Required for clinicians |
| ADHICS security controls | Not assessed | Assessment with the operating entity |
| Retention and deletion | No retention schedule | Define with the pilot partner |

## Interoperability

FHIR R4 export of Patient, Observation and RiskAssessment resources (`src/app/api/fhir/export/route.ts`). Malaffi lab import and TAMM entry are **proposed for production**. See [fhir-interoperability.md](fhir-interoperability.md).
